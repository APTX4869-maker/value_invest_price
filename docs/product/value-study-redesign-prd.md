# Value Study 双引擎产品重设计 PRD

日期：2026-05-02  
状态：已确认的产品设计基线  
适用范围：后续功能设计、UI 改版、后端数据模型与 API 演进

## 1. 背景与定位

当前网站已经具备观察池、公司分析、估值模型、同行比较、研究笔记、历史快照和 QQQ 发现池等能力。现有问题不在于缺少估值公式，而在于产品心智仍偏“功能菜单”，用户需要在多个页面之间自己拼出研究流程。

新版定位为本地个人美股研究工作台，核心是一个“双引擎”：

1. **发现雷达**：从更大的股票池里筛选可能低于实际价值、且值得继续研究的公司。
2. **公司研究档案**：对入选公司做业务、护城河、竞争力、财务质量、估值、同行和复盘的深度研究。

研究队列连接两者：

```text
发现雷达 -> 研究队列 -> 公司研究档案 -> 投资备忘录 -> 历史复盘
```

本产品不输出买卖指令，不接券商，不做自动交易提醒。所有估值结果都应表达为“当前价格隐含什么预期”“哪些假设最敏感”“是否值得继续研究”。

## 2. 核心用户诉求

### 2.1 大范围筛选公司

用户希望从 S&P 500 或自定义股票池中找出：

- 当前价格可能低于实际价值的公司。
- 数据质量足够、不完全依赖黑箱估算的公司。
- 财务质量、护城河和竞争风险综合看值得继续研究的公司。

### 2.2 深入研究入选公司

用户希望对入选公司系统研究：

- 公司怎么赚钱。
- 业务结构和增长驱动是什么。
- 护城河来自哪里，是否可持续。
- 行业竞争、替代、监管、周期风险是什么。
- 财务指标是否健康，现金流是否真实。
- 当前估值是否合理，关键假设是否过于乐观。
- 同行比较是否支持估值判断。
- 最终形成可复盘的结构化投资备忘录。

## 3. 一级信息架构

新版一级导航建议为：

1. **发现雷达**
   - S&P 500 默认池、QQQ 可选池、自定义池。
   - 扫描、评分、排序、解释、加入研究队列。

2. **研究队列**
   - 候选、初筛通过、深度研究中、已形成结论、复盘中。
   - 支持标签、多视图和下一步动作管理。

3. **公司档案**
   - 单家公司深度研究主场。
   - 一页纸结论 + 业务护城河 + 财务质量 + 估值 + 同行 + memo + 历史。

4. **投资备忘录**
   - 结构化 memo 集中管理。
   - 记录假设、结论、反证和复盘触发条件。

5. **历史复盘**
   - 估值快照、memo 版本、判断变化、复盘模式。

6. **设置与数据源**
   - 市场数据、SEC、指数池、FRED、Alpha Vantage、LLM Provider、导入导出。

## 4. 发现雷达

### 4.1 目标

发现雷达回答：

> 在 S&P 500、QQQ 或自定义股票池里，哪些公司最值得我下一步研究，为什么？

它是研究优先级排序器，不是荐股页。排序必须可解释。

### 4.2 股票池

默认池改为 **S&P 500**。

支持股票池：

- S&P 500：默认大范围市场扫描池。
- QQQ：可选科技成长子池。
- 自定义池：用户粘贴 ticker 列表，例如 AI 基建、支付公司、消费品牌、半导体。

S&P 500 注意事项：

- 虽然叫 500，但由于部分公司存在多股权类别，实际证券数通常约 503。
- 官方维护方是 S&P Dow Jones Indices。
- 免费、稳定、机器可读的成分股接口不一定可靠，因此需要数据源抽象和手动 CSV 覆盖能力。

参考：

- [Wikipedia: List of S&P 500 companies](https://en.wikipedia.org/wiki/List_of_S%26P_500_companies)
- [Slickcharts: S&P 500 Companies by Weight](https://www.slickcharts.com/sp500)
- [S&P Global: S&P 500 brochure](https://www.spglobal.com/spdji/en/documents/additional-material/sp-500-brochure.pdf?500=&p=)

### 4.3 扫描范围

第一版支持：

- Top 50
- Top 100
- 全部成分股

为避免一次性扫描过慢，采用：

- 分批扫描。
- 扫描结果缓存。
- 单家公司刷新。
- 扫描失败重试。
- 上次成功结果可继续展示。

### 4.4 综合研究优先级

排序用综合研究优先级，而不是只看低估幅度。

评分维度：

1. **估值吸引力**
   - 当前价相对综合合理中枢的折价/溢价。

2. **估值可信度**
   - 数据质量。
   - 模型一致性。
   - forward 数据来源。
   - 同行快照可用性。

3. **财务质量**
   - 收入增长。
   - 经营利润率。
   - FCF。
   - CAPEX。
   - SBC。
   - 净现金/负债。

4. **护城河**
   - 平台效应。
   - 品牌。
   - 规模。
   - 切换成本。
   - 技术壁垒。
   - 监管牌照。

5. **竞争风险**
   - 行业竞争强度。
   - 周期性。
   - 监管。
   - 技术替代。
   - 价格战。

6. **数据完整度**
   - SEC 财务数据是否完整。
   - 行情是否可用。
   - 同行是否可用。
   - 共识预期是否手动补充。

### 4.5 UI 规格

顶部：

- 股票池选择：S&P 500 / QQQ / 自定义池。
- 扫描范围：Top 50 / Top 100 / 全部。
- 操作：刷新成分股、刷新并扫描、只读取缓存。
- 状态：成分股日期、上次扫描时间、成功数、失败数、待补数据数。

主表格字段：

- Ticker
- 公司名
- 行业
- 权重
- 研究优先级
- 低估幅度
- 可信度
- 财务质量
- 护城河
- 竞争风险
- 数据完整度
- 操作

行展开内容：

- 为什么排名靠前。
- 估值解释。
- 财务解释。
- 护城河解释。
- 竞争风险。
- 缺失数据。
- 建议下一步。

操作：

- 加入研究队列。
- 打开公司档案。
- 刷新单家公司。
- 忽略。

后续视图：

- 行业热力图：观察低估线索集中在哪些行业。
- 矩阵视图：低估幅度 × 估值可信度。

## 5. 研究队列

### 5.1 目标

研究队列回答：

> 这些被发现的公司，我研究到哪一步了，下一步该做什么？

它取代“观察池”的产品心智，不只是关注列表，而是从市场筛选到深度研究之间的工作流管理层。

### 5.2 研究状态

固定 5 状态：

1. **候选**
   - 从发现雷达或手动添加而来。
   - 只是研究线索。

2. **初筛通过**
   - 估值、财务质量或业务质量有继续研究价值。

3. **深度研究中**
   - 正在补业务、护城河、财务质量、同行和 SEC 文档证据。

4. **已形成结论**
   - 已完成结构化投资备忘录，有明确判断和跟踪条件。

5. **复盘中**
   - 财报、价格或业务变化触发重新检查。

状态推进：

```text
候选 -> 初筛通过 -> 深度研究中 -> 已形成结论 -> 复盘中
复盘中 -> 已形成结论
```

### 5.3 标签体系

公司支持多标签。

标签类型：

- 主题：AI、云计算、半导体、支付、消费品牌。
- 研究：重点跟踪、等待回调、财报后复盘、待补数据。
- 风险：高竞争、强周期、监管、CAPEX 压力、利润率待验证。

第一版手动标签为主；后续发现雷达和 SEC 解析可以自动推荐标签。

### 5.4 UI 规格

默认看板视图：

- 5 列对应 5 状态。
- 卡片展示 ticker、公司名、标签、估值判断、研究优先级、下一步。
- 支持拖拽改变状态，或通过卡片详情抽屉修改。

列表视图：

- 适合公司数量较多时使用。
- 字段：ticker、状态、标签、估值判断、优先级、下一步、最近更新。
- 支持按标签、行业、状态、估值吸引力过滤。

卡片详情抽屉：

- 入队理由。
- 当前估值结论。
- 数据缺口。
- 待办事项。
- 最近快照。
- 操作：打开档案、刷新、移出队列、标记忽略。

## 6. 公司研究档案

### 6.1 目标

公司研究档案回答：

> 这家公司到底值不值得继续研究，以及当前价格是否合理？

它是深度研究主场，把现有公司分析、估值模型、同行比较、笔记和历史收拢到一个 ticker 档案里。

### 6.2 页面结构

顶部是一页纸结论：

- 公司名、ticker、行业、标签、研究状态。
- 当前判断：便宜 / 合理 / 偏贵 / 不确定。
- 一句话解释：为什么是这个判断。
- 当前价、合理中枢、保守/基准/乐观区间。
- 估值可信度。
- 数据质量警告。
- 下一步建议。
- 主操作：刷新研究包、一键估值、保存快照、写备忘录。

三个摘要卡：

1. **业务与护城河**
   - 怎么赚钱。
   - 核心业务。
   - 竞争优势。
   - 替代风险。

2. **财务质量**
   - 收入增长。
   - 经营利润率。
   - FCF。
   - CAPEX。
   - SBC。
   - 负债质量。

3. **关键风险**
   - 竞争。
   - 监管。
   - 周期。
   - 技术替代。
   - 管理层。
   - 估值假设。

模块标签：

- 概览
- 业务与护城河
- 财务质量
- 估值
- 同行比较
- 投资备忘录
- 历史复盘

### 6.3 业务与护城河模块

字段：

- 公司怎么赚钱。
- 收入结构与主要业务线。
- 增长驱动因素。
- 护城河类型：品牌、网络效应、规模、切换成本、技术壁垒、监管牌照。
- 护城河证据。
- 主要竞争对手。
- 替代风险。
- 监管/周期风险。
- 用户最终判断：强 / 中 / 弱 / 待确认。

AI/SEC 初稿状态：

- 待生成。
- 待确认。
- 已确认。
- 已编辑。
- 已驳回。

每条结论必须显示证据来源，或明确标记为“系统推断”。

### 6.4 财务质量模块

字段：

- 收入增长质量。
- 经营利润率趋势。
- FCF 与 Owner Earnings。
- CAPEX 是成长投入还是维持投入。
- SBC 稀释压力。
- 净现金/负债。
- ROIC 或近似资本回报指标。
- 财务质量结论：优秀 / 良好 / 一般 / 脆弱。

### 6.5 估值模块

默认交互：

- 一键估值。
- 首屏只展示目标区间、当前价格位置、可信度、主要敏感假设。

高级折叠：

- 收入增长。
- 折现率。
- terminal growth。
- 共识 EPS。
- 共识收入。
- EBITDA。
- FCF。
- 分析师目标价。
- 模型权重。
- 反向 DCF。

### 6.6 同行比较模块

功能：

- 推荐同行。
- 手动同行。
- 批量刷新同行估值。
- 相对估值表格。

表格字段：

- 价格/合理中枢。
- FCF Yield。
- 质量分。
- 隐含增长。
- 估值判断。

输出一句话：

> 当前公司相比同行是偏便宜、合理还是偏贵，为什么？

## 7. SEC + LLM 研究助手

### 7.1 目标

SEC + LLM 研究助手回答：

> 这家公司业务、护城河和风险的判断，有哪些来自年报/季报的证据？

它不是聊天机器人，而是公司档案里的研究助理。

### 7.2 工作流

```text
选择公司
-> 获取最新 10-K / 10-Q
-> 提取关键章节
-> LLM 生成结构化初稿
-> 展示证据出处
-> 用户确认/编辑/驳回
-> 写入公司档案
```

### 7.3 文档范围

第一版优先解析：

- 10-K Item 1：Business。
- 10-K Item 1A：Risk Factors。
- 10-K Item 7：MD&A。
- 10-Q MD&A：季度变化、管理层解释。
- 10-K 分部信息：能结构化提取时写入业务分部。

### 7.4 输出结构

LLM 输出必须为结构化 JSON：

- `business_model`
- `segments`
- `growth_drivers`
- `moat_sources`
- `competition`
- `key_risks`
- `financial_quality_notes`
- `follow_up_questions`
- `citations`

### 7.5 UI 规格

文档选择：

- 最新 10-K。
- 最新 10-Q。
- 历史文档。
- 显示 filing date、period、accession number、来源链接。

证据栏：

- 左侧展示提取到的原文证据。
- 每条证据有章节、摘要、原文摘录、来源链接。
- 支持复制到 memo。

初稿栏：

- 右侧展示 AI 初稿。
- 每段标记“待确认”。
- 操作：确认、编辑、驳回、重新生成。
- 确认后写入公司档案摘要。

质量与成本提示：

- provider。
- model。
- 生成时间。
- token 估计。
- 文档覆盖范围。
- 失败原因。

### 7.6 LLM Provider

设置项：

- `llm_enabled`
- `llm_provider_type`
- `llm_base_url`
- `llm_api_key`
- `llm_model`
- `llm_max_tokens`
- `llm_temperature`

后端抽象：

```text
ResearchLLMProvider
  -> OpenAICompatibleProvider
  -> future: ClaudeProvider / LocalProvider
```

业务层只调用统一接口：

```text
generate_company_research_draft(ticker, filing_sections, schema)
```

### 7.7 边界

- AI 生成内容默认是“待确认”。
- 所有结论必须有 SEC 证据引用，或标记为系统推断。
- 用户修改后的版本优先于 AI 初稿。
- 不生成投资建议。
- 失败时要区分 API 配置、文档抓取、token 限制、模型返回格式错误。

## 8. 结构化投资备忘录与复盘

### 8.1 目标

结构化备忘录回答：

> 我现在为什么这么判断，将来怎么知道自己错了？

它替代单纯自由 Markdown 笔记，成为研究闭环的最终沉淀。

### 8.2 字段

1. **当前结论**
   - 便宜 / 合理 / 偏贵 / 不确定。
   - 结论日期。
   - 对应估值快照。

2. **为什么关注**
   - 来自发现雷达的入队理由。
   - 用户补充。

3. **核心投资假设**
   - 3-5 条。

4. **业务与护城河判断**
   - 公司怎么赚钱。
   - 护城河强弱。
   - 竞争优势证据。
   - 主要竞争对手。

5. **财务质量判断**
   - 增长是否健康。
   - 利润率是否可持续。
   - FCF 是否真实。
   - CAPEX 和 SBC 是否侵蚀股东价值。

6. **估值判断**
   - 当前价相对合理中枢。
   - 最敏感假设。
   - 当前价格隐含预期。
   - 估值可信度。

7. **我可能错在哪里**
   - 反证清单。

8. **复盘触发条件**
   - 财报发布。
   - 价格偏离合理区间。
   - 核心假设被证伪。
   - 公司业务结构变化。
   - 用户手动设置复盘日期。

### 8.3 交互

- 从公司档案生成草稿。
- 自动带入估值结论、SEC 初稿、财务质量摘要、同行结论。
- 用户必须确认关键字段，才能标记“已形成结论”。
- 每次保存 memo 生成版本。
- 历史复盘页可对比 memo 版本。
- 现有 Markdown 作为“自由补充”保留。

### 8.4 复盘模式

复盘时展示：

- 当时结论。
- 当时价格。
- 当时合理区间。
- 当时核心假设。
- 当前最新数据。

用户填写：

- 哪些假设成立。
- 哪些假设失效。
- 判断是否更新。
- 是否保存新快照。

## 12. 错误与空状态

必须区分：

- 股票池成分抓取失败。
- 行情抓取失败。
- SEC companyfacts 失败。
- SEC filing 抓取失败。
- 估值模型失败。
- LLM API 未配置。
- LLM token 超限。
- LLM 返回格式错误。
- ticker 不支持。
- ETF/基金/非经营公司不适用。
- 非美元申报需要手动汇率转换。

空状态示例：

- 股票池未扫描：提示选择范围并扫描。
- 公司无 SEC 数据：提示 ETF/基金/ADR/非美申报风险。
- LLM 未配置：引导到设置，但不阻塞手动研究。
- AI 初稿无引用：标记为低可信，不允许直接确认。
- 估值低可信：提示补共识、同行或手动假设。

## 13. 实现优先级

### 第一阶段：双引擎骨架

目标：先把产品结构从“功能菜单”升级为“发现雷达 + 研究队列 + 公司档案”。

范围：

1. S&P 500 发现雷达 Top 50 / Top 100 扫描。
2. 保留 QQQ 和自定义池。
3. 研究队列 5 状态 + 多标签。
4. 公司档案 tabs 整合现有公司分析、估值、同行、笔记、历史。
5. 结构化备忘录第一版。

### 第二阶段：深度研究能力

范围：

1. 公司档案一页纸结论增强。
2. 业务与护城河模块。
3. 财务质量模块。
4. 结构化 memo 与现有 Markdown 兼容。

### 第三阶段：SEC + LLM 助手

范围：

1. SEC filing section 抽取。
2. LLM Provider 抽象。
3. 业务/护城河/风险初稿。
4. 初稿确认、编辑、驳回。
5. 写入公司档案。

### 第四阶段：复盘闭环

范围：

1. memo 版本化。
2. 快照与 memo 关联。
3. 复盘模式。
4. 研究队列自动进入“复盘中”。
5. 行业热力图和低估×可信度矩阵。

## 14. 开发原则

- 默认面向非专业个人投资者，用白话解释专业指标。
- 发现雷达只生成研究线索，不生成买卖建议。
- 公司档案必须能解释“为什么便宜/合理/偏贵”。
- 估值结果必须展示可信度、数据来源和敏感假设。
- SEC + LLM 初稿默认待确认，不自动成为最终判断。
- 用户手动确认和编辑的内容优先于系统生成内容。
- 新增估值公式必须有后端测试。
- 修改前端主流程后必须运行 `npm run build`。
- 新增数据源解析必须覆盖失败提示和至少一组测试样本。
